# Crystal Match

HTML5 Canvas match-3 игра Milevora team для браузерных игровых платформ. Проект работает без Unity, npm, React и сборщиков.

## Технологии

- HTML, CSS и JavaScript
- Canvas 2D
- Web Audio API
- WebP-спрайты и WAV-звуки
- платформенные SDK через отдельные адаптеры

Точка запуска: `index.html`.

## Структура

- `js/platform-core.js` — общий запуск, Canvas, игровой цикл, системные события и качество графики.
- `js/game*.js` — игровая логика, эффекты, экономика, цели и режим уровней.
- `js/render*.js` — отрисовка поля и интерфейса.
- `js/input.js` — мышь, touch и жесты.
- `js/i18n.js` — русская и английская локализации.
- `js/audio.js` — звуки и музыка.
- `js/levels.js` — уровни 1–100.
- `platforms/` — конфигурации и адаптеры площадок.
- `tools/build-platform.ps1` — создание отдельных платформенных архивов.
- `sprites/`, `sounds/` и `fonts/` — игровые ресурсы; интерфейс использует локальный variable-шрифт CrystalUI (Rubik, OFL 1.1).

Порядок подключения скриптов в `index.html` важен: файлы расширяют общие классы через prototype.

## Режимы

- Бесконечный режим на поле 7x8.
- Режим прохождения со звёздами, главами и кубками.
- Уровни 1–100 заданы вручную.
- Уровни после 100 детерминированно генерируются по номеру и одинаковы для всех игроков.

Игра поддерживает обычные совпадения, каскады, камни, линейные спецфишки, бомбы, радугу и три бустера.

## Прогресс

Постоянные данные:

- монеты;
- общий опыт и звание;
- ежедневный и рекламный бонусы;
- открытые уровни;
- звёзды и кубки глав;
- обработанные покупки.

Новый игрок получает 5000 монет. Без серверного профиля используется `localStorage`.

В Яндекс Играх главный объект облачного прогресса: `crystalProgress`. В VK обычный прогресс хранится в `localStorage` и VK Storage.

## Глобальные системы

### Сохранения

- Игра всегда сохраняет прогресс локально и передаёт изменения наружу через callbacks платформенного адаптера.
- Яндекс загружает облачный `crystalProgress` до создания игры и использует его как основу прогресса на разных устройствах.
- VK хранит обычный прогресс только в `localStorage` и VK Storage; Archi backend не используется как хранилище save.
- Обычные изменения прогресса объединяются платформенными адаптерами в один снимок: опыт отправляется с задержкой, а завершение режима и важные изменения ускоряют запись без серии параллельных запросов.
- Подтверждённые покупки сохраняются отдельным приоритетным путём и не зависят от очереди обычного прогресса.
- Перед скрытием или закрытием страницы ожидающие сохранения принудительно отправляются.
- При возврате в игру облако перечитывается, если нет несохранённых локальных изменений.
- Покупки защищены списком обработанных событий; повторное событие не меняет баланс второй раз.
- Без доступного SDK или авторизации игра полностью работает через `localStorage`.

### Масштабирование

- Canvas занимает viewport, а его внутреннее разрешение равно CSS-размеру, умноженному на ограниченный DPR.
- Вся геометрия интерфейса вычисляется централизованно в `Renderer.computeLayout()` из ширины, высоты, safe-area, режима игры и размера поля.
- Размер клетки выбирается по меньшему из доступных ограничений ширины и высоты; поле остаётся целым и центрируется.
- Используются отдельные адаптивные компоновки для узкого портрета и широкого экрана, без масштабирования готового интерфейса целиком.
- При `resize`, смене ориентации, режима или размера поля layout пересчитывается, а зависимые кэши очищаются.

### Производительность

- Есть три профиля качества с автоматическим переключением по устойчивому FPS на мобильных и десктопных устройствах.
- Профиль ограничивает DPR, blur, плотность декора, количество эффектов и летящих монет.
- Статичные панели, рамки, монеты, бустеры и фишки кэшируются под актуальный размер; кэши пересоздаются только при изменении layout или качества.
- Количество частиц и эффектов жёстко ограничено, более ранние эффекты удаляются при превышении лимита.
- Звук и системные процессы приостанавливаются при скрытии страницы, потере фокуса и событиях паузы площадки; нативная реклама и платёжные окна удерживают аудиопаузу до окончательного закрытия оверлея.

### Платформы

- Игровая логика не знает о конкретном SDK и работает через единый контракт callbacks.
- `js/platform-core.js` отвечает за общий жизненный цикл, а `platforms/<name>/` содержит только SDK, профиль, облако, рекламу, покупки и рейтинги площадки.
- Сборщик копирует общую игру и ровно один выбранный адаптер, поэтому код разных площадок не попадает в один релизный архив.

### VK Mini Apps

- За первое прохождение уровня награду монетами можно один раз удвоить за rewarded-рекламу; повторное прохождение не создаёт новый рекламный бонус.

- Одна VK-сборка работает во ВКонтакте и Одноклассниках; OK-режим определяется по `vk_client=ok`, отдельного архива приложения нет.
- На `desktop_web` и `desktop_web_ok` адаптер запрашивает высоту viewport через VK Bridge и расширяет окно до 911 и 1000 px соответственно; мобильные платформы resize не вызывают.
- В VK/OK боковая desktop-компоновка включается от области `720x460`: поле центрируется по игровой зоне и сдвигается вправо только при нехватке места для колонки целей слева; при меньшем iframe сохраняется компактная компоновка.
- В режиме уровней VK/OK всегда доступна внутриигровая кнопка выхода с подтверждением: на широком экране рядом с полем, в мобильной компоновке отдельной нижней строкой; Яндекс использует прежнюю навигацию.
- Кнопка разработчика «Наши игры» и её обработчик отключены платформенным флагом только в VK-сборке.
- рабочий адаптер и локальная копия VK Bridge: `platforms/vk/`;
- профиль, язык, VK Storage, rewarded/interstitial-реклама и покупки подключены; rewarded-видео ожидает готовность и запускается через waterfall VK Bridge с резервным стандартным показом, успешные interstitial-показы ограничены одним разом в 2 минуты, а выход из итогового окна переключает состояние в меню до ожидания ответа рекламы;
- sticky-баннер VK/OK включается только при поддержке площадкой, размещается снизу в режиме `resize` без пользовательского закрытия и временно скрывается на время полноэкранной рекламы и оплаты;
- бесконечный рейтинг хранится в VK, загружается через глобальный VK API-рейтинг типа `score` и показывается во внутриигровом окне;
- новый рекорд бесконечного режима проверяется каждые 30 секунд и отправляется в VK подписанным запросом через Archi backend без системного окна; запрос выполняется только для нового неподтверждённого рекорда, а `endlessSubmittedScore` обеспечивает повторную отправку после сбоя и перезапуска;
- рейтинг общего количества звёзд работает через Archi backend, который хранит только топ-10 каждой площадки; результат вне топа остаётся в прогрессе игрока и показывается локально без места;
- общий опыт и звание сохраняются в обычном прогрессе VK, серверный XP-рейтинг отключён;
- результат по звёздам отправляется только когда по клиентскому кэшу может войти в топ-10; backend-рейтинги кэшируются на клиенте на 6 часов, а нативный бесконечный рейтинг VK обновляется при каждом открытии вкладки без длительного кэша;
- проверки backend-событий выполняются после оплаты ограниченными попытками и при восстановлении ожидающей покупки; обычный старт и открытие магазина не опрашивают backend без ожидающего подтверждения;
- VK/OK-клиент передаёт версию backend-протокола, чтобы устаревшие сборки не создавали операции рейтингов в YDB;
- покупки начисляются только по подтверждённым backend-событиям `grant` и `refund`, сохраняются в VK Storage и подтверждаются через ACK; ожидание подтверждения автоматически истекает через 24 часа;
- `platforms/vk/backend-client.js` отвечает за короткие безопасные HTTP-запросы и общий backoff при перегрузке backend, а `backend-integration.js` связывает backend с адаптером;
- при недоступности backend обычный прогресс и бесплатные функции продолжают работать.
- В VK и OK покупки открываются единым вызовом `VKWebAppShowOrderBox`; начисление выполняется только по подтверждённым backend-событиям `pending/ack`. Для VK используются цены 5/10/20/45 голосов, для OK — 19/49/99/199 ОК.
- В OK бесконечный рейтинг отправляется и загружается через Archi backend, в VK используется нативный рейтинг площадки; оба отображаются во внутриигровом окне рейтинга и в итоговом окне бесконечного режима.

- После нативных overlay VK/OK адаптер сбрасывает время кадра, пересоздаёт поверхность Canvas и короткой проверкой подтверждает восстановление единственного цикла `requestAnimationFrame`.
- Запуск VK/OK ограничивает ожидание шрифта, VK Bridge, профиля и VK Storage таймаутами; недоступность платформенного ответа не должна удерживать стартовый экран.

### Local

`platforms/local/` запускает игру без SDK, площадок и backend с локальным прогрессом.

### CrazyGames

- адаптер: `platforms/crazygames/`;
- прогресс хранится через Data Module CrazyGames SDK с локальным резервным сохранением;
- в текущей Basic-сборке реклама отключена: повтор ежедневной награды скрыт, магазин выдаёт бесплатный бонус раз в 30 минут, а продолжение уровня один раз добавляет ходы без рекламы;
- единственный рейтинг площадки получает только новый опыт текущей недели: прирост накапливается локально, объединяется и отправляется не чаще одного раза в 30 секунд; постоянный опыт звания повторно не отправляется;
- системная таблица рейтинга открывается интерфейсом CrazyGames, поэтому внутриигровая кнопка кубка скрыта;
- покупки и игровые события используют CrazyGames SDK без Archi backend;
- платформенная сборка содержит только общий код игры и CrazyGames-адаптер.

## Запуск и сборка

Локальный сервер:

`python -m http.server 8000`

Проверка JavaScript:

`Get-ChildItem js,platforms -Filter *.js -Recurse | ForEach-Object { node --check $_.FullName }`

Сборка:

`powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\build-platform.ps1 -Platform yandex`

Вместо `yandex` можно указать `vk`, `crazygames` или `local`. Результат создаётся в `output/`, которая не хранится в Git.

Каждый архив содержит общую игру и только адаптер выбранной площадки.

Пути файлов внутри ZIP всегда записываются через `/`. После сборки проверяются структура архива и наличие обязательных файлов.

Workflow `.github/workflows/deploy-vk-pages.yml` собирает единую VK/OK-версию из `master` командой VK-сборки и публикует только `output/vk` на GitHub Pages основного приложения.

Перед релизом проверяется консоль браузера: в актуальной платформенной сборке не должно быть ошибок и вызовов устаревших методов SDK.
