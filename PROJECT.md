# Crystal Match

Актуально на 24 июля 2026 года.

## Назначение

Crystal Match — премиальная HTML5 Canvas match-3 игра Milevora team. Основная площадка текущей версии — Яндекс Игры. Игра работает без Unity, npm, сборщиков и внешнего игрового движка.

Точка запуска: `index.html`.

Зафиксированная сборка для модерации Яндекс Игр:

- commit: `c88edb7`
- tag: `yandex-moderation-2026-07-23`

## Технологии

- HTML5
- CSS
- JavaScript
- Canvas 2D
- Web Audio API
- Yandex Games SDK
- WebP-спрайты
- WAV-звуки

Все скрипты подключаются обычными тегами `script` в строгом порядке. Модули расширяют глобальные классы через prototype, поэтому порядок в `index.html` менять без проверки нельзя.

## Состав релиза

В релиз и Git входят только:

- `index.html`
- `css/`
- `js/`
- `sounds/`
- `sprites/`
- `.gitignore`

Папка `output/`, временные изображения, архивы, инструменты и локальные материалы в Git не входят.

## Быстрый запуск

Из корня проекта:

`python -m http.server 8000`

Открыть:

`http://localhost:8000`

Локально запрос `/sdk.js` может завершаться ошибкой — игра должна перейти на локальное хранение и продолжить работу. Полную проверку рекламы, платежей, профиля и лидербордов выполнять в окружении Яндекс Игр.

Проверка синтаксиса:

`Get-ChildItem js -Filter *.js | ForEach-Object { node --check $_.FullName }`

## Игровые режимы

### Бесконечный

- поле 7x8;
- 5 цветов;
- бесконечный набор результата;
- растущее давление камней;
- цели дают монеты;
- при отсутствии ходов можно использовать бустеры или завершить раунд;
- результат регулярно отправляется в лидерборд и окончательно отправляется при завершении.

### Уровни

- уровни 1–100 заданы вручную в `js/levels.js`;
- уровни после 100 создаются детерминированным генератором по номеру уровня;
- один номер уровня даёт одинаковые условия всем игрокам;
- главы содержат по 10 уровней;
- после победы открываются следующие два уровня;
- рекомендуемый уровень — `highestUnlockedLevel - 1`;
- максимум 3 звезды за уровень;
- все 30 звёзд главы дают кубок;
- после 25 уровня при отсутствии ходов разрешено продолжение через бустеры и экономические механики;
- за рекламу можно один раз получить 5 дополнительных ходов;
- первые уровни содержат постоянные обучающие подсказки.

Размер поля постепенно растёт от 5x5 до 7x8. Поле 8x8 не используется.

## Основные механики

- обычный match-3;
- обмен соседних фишек мышью, тапом или свайпом;
- обмен без совпадения откатывается;
- каскады и падение новых фишек;
- стартовое поле без готовых совпадений;
- линейная спецфишка;
- цветная бомба;
- радужная спецфишка;
- разрушаемые камни;
- молоток, бомба и радуга как покупаемые за монеты бустеры;
- стоимость каждого бустера растёт на 20% только после использования этого же бустера в текущем раунде.

Базовые цены бустеров:

- молоток: 800;
- бомба: 1800;
- радуга: 4500.

## Экономика

Новый игрок получает 5000 монет. Без SDK и без серверного профиля используются локальные данные.

Источники монет:

- игровые цели;
- награды за уровни;
- ежедневный бонус;
- удвоение ежедневного бонуса за рекламу;
- 5000 монет за rewarded-рекламу в магазине с ожиданием 30 минут;
- покупки.

Пакеты покупок:

- `coins_10000` — 10 000 монет;
- `coins_25000` — 25 000 монет;
- `coins_60000` — 60 000 монет;
- `coins_150000` — 150 000 монет.

Цена и изображение валюты должны браться из каталога Yandex Payments SDK. Значения в коде используются как резервное отображение.

Обработанные purchase tokens хранятся в количестве не более 50 для защиты от повторного начисления.

## Сохранение прогресса

Главный облачный ключ:

`crystalProgress`

Структура:

- `coins` — постоянный баланс;
- `rankXp` — общий опыт;
- `dailyBonus` — серия и даты получения;
- `adBonus` — время последней рекламной награды магазина;
- `levelProgress.highestUnlockedLevel` — максимальный открытый уровень;
- `levelProgress.stars` — лучший результат звёзд по уровням;
- `levelProgress.chapterTrophies` — полученные кубки глав;
- `coinPurchaseTokens` — уже обработанные покупки.

Облачное сохранение работает через `player.getData()` и `player.setData(payload, true)`, если объект игрока поддерживает эти методы.

Правила синхронизации:

- при запуске сначала загружается единый объект `crystalProgress`;
- монеты сохраняются примерно через 450 мс, критические начисления и списания — немедленно;
- ежедневный и рекламный бонусы сохраняются примерно через 350 мс или немедленно после получения;
- прогресс уровней сохраняется примерно через 500 мс или немедленно после победы;
- общий опыт отправляется с задержкой 30 секунд и принудительно в важных точках;
- незавершённые записи отправляются при `pagehide` и `beforeunload`;
- при возврате фокуса данные повторно читаются с сервера;
- при ошибке записи значение остаётся ожидающим повторной отправки;
- локальная копия хранится в `localStorage`.

Локальные ключи:

- `crystal-match-coins`;
- `crystal-match-rank-xp`;
- `crystal-match-daily-bonus`;
- `crystal-match-ad-bonus`;
- `crystal-match-level-progress`;
- `crystal-match-purchase-tokens`;
- `crystal-match-best-score`.

Не возвращать старые раздельные облачные поля: до релиза совместимость с ними не требуется.

## Яндекс Игры

SDK подключается как `/sdk.js`.

Последовательность запуска:

1. `YaGames.init()`;
2. получение языка из `ysdk.environment.i18n.lang`;
3. применение локализации;
4. вызов `LoadingAPI.ready()`;
5. загрузка игрока и прогресса;
6. создание игры и первого интерактивного меню.

Лидерборды:

- `CrystalTreasuresMatch3` — бесконечный режим;
- `CrystalTreasuresStars` — общее количество звёзд;
- `CrystalTreasuresXP` — общий опыт игрока.

Используются:

- rewarded-реклама;
- полноэкранная реклама;
- sticky banner;
- внутриигровые покупки;
- имя игрока;
- ссылка «Наши игры» через Games API;
- пауза звука и музыки при рекламе, потере фокуса и скрытии страницы.

Для sticky banner в консоли Яндекс Игр должны быть включены баннер и управление им через API. Платформа всё равно может скрыть баннер при недостаточной ширине окна.

## Локализация

Поддерживаются:

- русский;
- английский.

Язык берётся из SDK, а локально — из языка браузера. Любой новый пользовательский текст добавлять в обе секции `js/i18n.js`; не размещать строки прямо в рендере или игровой логике.

## Звук

Файлы:

- `fishka.wav` — матч и молоток;
- `bomb.wav` — бомба;
- `luch.wav` — линейная спецфишка;
- `rainbow.wav` — радуга;
- `stone.wav` — камень;
- `coins.wav` — начисление монет.

Музыка генерируется кодом в `js/audio.js`.

Ограничения:

- максимум 9 одновременно активных файловых звуков;
- максимум 3 экземпляра одного звука;
- звук немедленно выключается кнопкой;
- звук приостанавливается при скрытии страницы, потере фокуса и показе рекламы.

## Графика и производительность

- три адаптивных профиля качества: 0–2;
- профиль автоматически меняется по фактическому FPS;
- отдельные лимиты DPR для мобильных и десктопа;
- ограничены эффекты, осколки и летящие монеты;
- тяжёлые эффекты упрощаются на слабом профиле;
- статические части интерфейса кэшируются;
- WebP используется для всех растровых спрайтов;
- поле и интерфейс рассчитаны на мобильную портретную и десктопную версии;
- на мобильном в альбомной ориентации показывается просьба повернуть экран;
- разнесённого бокового desktop-layout в игре быть не должно.

При оптимизации сначала проверять каскады с большим количеством спецфишек: это наиболее тяжёлый сценарий.

## Git и восстановление

Основная ветка: `master`.

Текущая контрольная точка Яндекса:

`git switch --detach yandex-moderation-2026-07-23`

Вернуться к рабочей ветке:

`git switch master`

Не продолжать разработку из detached HEAD. Для отдельной платформы создавать ветку от стабильного тега, например `codex/vk-games`.

GitHub CLI авторизован под аккаунтом `ArchiXIII`, но удалённый репозиторий на момент создания этого файла ещё не подключён. Репозиторий должен быть приватным. После подключения необходимо отправлять ветки и теги:

`git push origin master`

`git push origin --tags`

## Подготовка других платформ

Не создавать копию всей игры для каждой площадки. Общая игровая логика должна оставаться единой, а интеграции платформ — тонкими адаптерами.

План:

- общая игровая часть;
- адаптер Яндекс Игр;
- адаптер VK Mini Apps/VK Bridge;
- локальный адаптер;
- отдельные идентификаторы товаров, лидербордов, рекламы и ссылок;
- отдельные выходные папки сборок;
- отдельные release tags для каждой площадки.

В сборке Яндекса не должно быть SDK, рекламы и ссылок VK. В сборке VK не должно быть интеграций Яндекса. Общий прогресс между площадками невозможен без собственного сервера и связывания аккаунтов.

## Перед релизом

1. Проверить `node --check` для всех JS-файлов.
2. Запустить локально и проверить оба языка.
3. Проверить desktop и мобильную портретную компоновку.
4. Проверить начало и завершение обоих режимов.
5. Проверить отсутствие ходов, выход, рекламу за ходы и повторный запуск.
6. Проверить облачную синхронизацию между двумя браузерами под одним аккаунтом.
7. Проверить ежедневный бонус и рекламные cooldown после перезагрузки.
8. Проверить каждую покупку и защиту от повторного начисления.
9. Проверить три лидерборда.
10. Проверить паузу звука при рекламе, скрытии вкладки и потере фокуса.
11. Проверить производительность при массовом каскаде спецфишек.
12. Создать commit и отдельный release tag.
13. Отправить ветку и все теги в приватный GitHub.
