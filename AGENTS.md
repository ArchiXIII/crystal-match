# Правила работы с проектом

1. Не выводить код в чат.
2. Не добавлять комментарии к очевидному коду. Объяснять логику только по прямому запросу.
3. Оптимизировать JavaScript для мобильного Web: избегать лишних аллокаций в циклах обновления, утечек памяти и тяжёлых эффектов.
4. Тратить время и токены только на то, что напрямую влияет на качество игры.
5. Не переусложнять игровые системы без необходимости.
6. Не обновлять `PROJECT.md` после обычных изменений. Обновлять его только непосредственно перед онлайн-коммитом по запросу пользователя или по отдельному прямому запросу на изменение сводки.
7. Держать `PROJECT.md` кратким: только стабильная архитектура, важные интеграции, восстановление и сборка. Не добавлять мелкие визуальные и игровые правки.
8. Делить код по подсистемам и ответственности, а не механически по количеству строк. Один файл должен решать одну понятную задачу.
9. Ориентир для рабочего JavaScript-модуля — до 600–800 строк. После 800 строк проверять возможность разделения, после 1200 строк разделять обязательно, кроме таблиц данных и стороннего кода.
10. Не создавать множество микрофайлов. Небольшие тесно связанные функции хранить вместе, а общение модулей вести через узкий стабильный интерфейс.
11. Отделять игровую логику, отрисовку, ввод, данные, ресурсы и платформенные SDK. Платформенный код не должен проникать в общую игру.
12. Все текстовые файлы хранить в UTF-8 и проверять локализации после массовых правок, чтобы не допускать повреждения кириллицы.
13. Исходники, платформенные конфигурации и инструменты хранить в Git. Сборки, архивы, резервные копии, временные файлы, ключи и токены в репозиторий не добавлять.
14. Перед важным онлайн-коммитом проверять синтаксис, собирать архивы целевых площадок, выполнять короткий запуск на десктопе и мобильном размере и обновлять `PROJECT.md`.
